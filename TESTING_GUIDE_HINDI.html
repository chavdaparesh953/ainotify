2. Meta WhatsApp Cloud API सेटअप और रियल टेस्टिंग Meta Integration

अपने खुद के रियल मोबाइल नंबर पर लाइव WhatsApp मैसेज भेजकर चेक करना।

⚠️
सैंडबॉक्स जरूरी सूचना: यदि आप Meta के टेस्ट नंबर से मैसेज भेज रहे हैं, तो अपने मोबाइल नंबर को Meta के Manage phone number list में जोड़ना अनिवार्य है।
स्टेप 1: Meta Developers से क्रेडेंशियल्स निकालें
Meta for Developers में जाएं ➜ WhatsApp ➜ API Setup.
यहाँ से Phone number ID, WhatsApp Business Account ID, और Temporary Access Token कॉपी करके अपने .env में सेव करें।
स्टेप 2: अपना मोबाइल नंबर सैंडबॉक्स में रजिस्टर करें
API Setup पेज पर **To** ड्रॉपडाउन में Manage phone number list पर क्लिक करें। अपना +91 वाला नंबर जोड़ें और WhatsApp पर आए 6 अंकों के OTP से वेरीफाई करें।
स्टेप 3: टर्मिनल से सीधा मोबाइल पर टेस्ट मैसेज भेजें
बिना किसी Shopify स्टोर के भी आप सीधा अपने मोबाइल पर लाइव मैसेज टेस्ट कर सकते हैं:
टर्मिनल टेस्ट कमांड 
# 1. Meta के डिफ़ॉल्ट hello_world टेम्पलेट से टेस्ट करें:
node scripts/test-live-whatsapp.js +919876543210 --template hello_world

# 2. आर्डर कन्फर्मेशन टेम्पलेट से टेस्ट करें:
node scripts/test-live-whatsapp.js +919876543210 --template order_confirmation --name "Paresh" --order "#ORD-101" --total "₹2,499.00"
स्टेप 4: Meta इनबाउंड वेबहुक सेट करें (बटन रिप्लाई के लिए)
npm run dev:tunnel से Ngrok URL निकालें। Meta App ➜ WhatsApp ➜ Configuration में जाएं:
• Callback URL: https://<NGROK-ID>.ngrok-free.app/api/webhooks/meta
• Verify Token: omnipulse_meta_verify_token_123
• messages इवेंट को Subscribe करें।

3. SMS प्रोवाइडर और ऑटोमैटिक फॉलबैक टेस्टिंग SMS Gateways

Twilio & Fast2SMS इंटीग्रेशन और यदि कस्टमर WhatsApp पर न हो तो SMS फॉलबैक चेक।

Twilio गेटवे

कंसोल: Twilio Console

कीज़: accountSid, authToken, fromNumber

ग्लोबल कवरेज

Fast2SMS गेटवे

कंसोल: Fast2SMS Dev API

कीज़: apiKey, senderId (DLT 6-Character)

इंडिया DLT अप्रूव्ड
टेस्ट 3.1: फ्री मॉक SMS सिम्युलेशन (बिना पैसे खर्च किए)
सिस्टम में बिना बैलेंस के भी पूरा SMS लॉजिक टेस्ट करने की सुविधा है:
Terminal 
npm run test:sms
टेस्ट 3.2: WhatsApp-to-SMS फॉलबैक लॉजिक की पुष्टि
यदि कोई नंबर WhatsApp पर एक्टिव नहीं है (Meta Error 131026), तो बैकग्राउंड वर्कर तुरंत WhatsApp मैसेज के मार्कडाउन (*बोल्ड*, _इटैलिक_) को हटाकर उसे साफ SMS में बदलकर Twilio या Fast2SMS से भेज देता है।
डेटाबेस में स्टेटस SMS_FALLBACK और चैनल SMS दर्ज होगा।

4. Shopify स्टोर कनेक्शन और ई-कॉमर्स ऑटोमेशन Shopify Integration

आर्डर क्रिएशन, COD वेरिफिकेशन, Shopify Tags (`COD-Confirmed`), और एबंडन्ड कार्ट प्रोटेक्शन।

स्टेप 4.1: Shopify Partners पर Dev Store और Custom App बनाएं
1. Shopify Partners पर फ्री Dev Store बनाएं।
2. स्टोर में Settings ➜ Apps and sales channels ➜ Develop apps पर जाएं।
3. Admin API Scopes में read_orders, write_orders, read_checkouts, write_checkouts ऑन करें।
4. ऐप इनस्टॉल करके अपना Admin API access token (shpat_...) निकालें।
स्टेप 4.2: मर्चेंट डैशबोर्ड में स्टोर कनेक्ट करें
http://localhost:3000/dashboard/stores खोलें ➜ Connect New Store दबाएं ➜ Store URL, Token, और Webhook Secret भरकर कनेक्ट करें।
स्टेप 4.3: बिना डमी आर्डर प्लेस किए इंस्टेंट वेबहुक टेस्ट चलाएं
हमारे सिम्युलेटर से अपने रियल मोबाइल नंबर पर तुरंत Shopify आर्डर का WhatsApp मैसेज पाएं:
Terminal 
# अपने नंबर पर आर्डर वेबहुक सिम्युलेट करें:
node scripts/simulate-webhook.js +919876543210
स्टेप 4.4: COD फ्लो और Shopify पर 'COD-Confirmed' टैग लगना टेस्ट करें
कमांड चलाएं: npm run simulate:cod.
जब कस्टमर WhatsApp पर कन्फर्म करता है, तो हमारा सर्वर Shopify Admin API कॉल करके उस आर्डर पर COD-Confirmed टैग और टाइमलाइन नोट जोड़ देता है।
स्टेप 4.5: एबंडन्ड कार्ट और ऑर्गेनिक रिकवरी प्रोटेक्शन टेस्ट
कमांड चलाएं: npm run simulate:abandoned.
यदि कस्टमर ने चेकआउट अधूरा छोड़ने के बाद खुद से स्टोर पर जाकर आर्डर पूरा कर लिया, तो हमारा वर्कर उसे पहचानकर मैसेज नहीं भेजता ताकि कस्टमर परेशान न हो।

5. WooCommerce स्टोर कनेक्शन और ऑटोमेशन WooCommerce Integration

WordPress REST API कीज़, वेबहुक क्रिएशन, और आर्डर स्टेटस अपडेट।

स्टेप 5.1: WooCommerce REST API Keys बनाएं
वर्डप्रेस एडमिन ➜ WooCommerce ➜ Settings ➜ Advanced ➜ REST API.

स्टेप 5.2: WooCommerce वेबहुक बनाएं
WooCommerce ➜ Settings ➜ Advanced ➜ Webhooks ➜ Add Webhook:
• Topic: Order created
• Delivery URL: https://<NGROK-ID>.ngrok-free.app/api/webhooks/receive
• Secret: एक सीक्रेट पासवर्ड सेट करें।
स्टेप 5.3: ऑटोमेटेड WooCommerce स्टेटस सिंक टेस्ट चलाएं
कस्टमर द्वारा WhatsApp पर कन्फर्म करने पर WooCommerce आर्डर का स्टेटस processing और कैंसिल करने पर cancelled करने का टेस्ट:
Terminal

7. सिक्योरिटी, HMAC सिग्नेचर और एज केस टेस्टिंग Security Auditing

अनधिकृत या फर्जी वेबहुक को HTTP 401 के साथ रिजेक्ट करने की जांच।

सिक्योरिटी टेस्ट 1: फर्जी HMAC सिग्नेचर रिजेक्शन (401 Unauthorized)
गलत सिग्नेचर के साथ वेबहुक भेजें। सर्वर को इसे तुरंत HTTP 401 देना चाहिए:
cURL Tamper Test 
curl -X POST http://localhost:4000/api/webhooks/receive \
  -H "Content-Type: application/json" \
  -H "X-Shopify-Shop-Domain: test-brand.myshopify.com" \
  -H "X-Shopify-Topic: orders/create" \
  -H "X-Shopify-Hmac-Sha256: FAKE_TAMPERED_BASE64_SIGNATURE==" \
  -d '{"id":99999,"total_price":"999.00"}'
सिक्योरिटी टेस्ट 2: अनरजिस्टर्ड स्टोर रिजेक्शन (404 Not Found)
यदि कोई वेबहुक ऐसे डोमेन से आता है जो हमारे डेटाबेस में कनेक्ट नहीं है, तो सर्वर HTTP 404 Not Found लौटाएगा।
सिक्योरिटी टेस्ट 3: अमान्य या लैंडलाइन नंबर प्रोटेक्शन
यदि आर्डर में कोई लैंडलाइन नंबर है, तो सर्वर या वर्कर क्रैश नहीं होगा। वह डेटाबेस में FAILED स्टेटस और रीज़न INVALID_OR_MISSING_PHONE रिकॉर्ड करेगा।

9. ट्रबलशूटिंग और मुख्य एरर कोड्स का समाधान Error Matrix

अक्सर आने वाले सामान्य एरर्स और उनका तुरंत समाधान।

एरर कोड / लक्षण कारण समाधान (Fix)
Meta Error 190 Access Token एक्सपायर हो गया है या गलत है। Meta Developer Console ➜ API Setup से नया टोकन निकालें और .env में अपडेट करें।
Meta Error 131026 नंबर WhatsApp पर नहीं है या सैंडबॉक्स में जोड़ा नहीं है। सैंडबॉक्स में टेस्ट कर रहे हैं तो नंबर को 'Manage phone number list' में ऐड करें। लाइव में 'Fallback to SMS' ऑन रखें।
Meta Error 131047 24 घंटे की सर्विस विंडो बंद हो चुकी है। बिज़नेस को हमेशा प्री-अप्रूव्ड टेम्पलेट (type: template) से ही पहला मैसेज भेजना होगा।
Meta Error 100 टेम्पलेट का नाम मैच नहीं हो रहा। जांचें कि टेम्पलेट का नाम Meta Templates Manager में और कोड में बिलकुल एक समान है (केस-सेंसिटिव)।
HTTP 401 Invalid Signature वेबहुक सीक्रेट मिसमैच। सुनिश्चित करें कि Shopify/Woo में जो सीक्रेट है, वही डेटाबेस के स्टोर रिकॉर्ड में webhookSecret है।
ECONNREFUSED 127.0.0.1:6379 Redis सर्वर बंद है। टर्मिनल में redis-server या Mac पर brew services start redis चलाएं।
Ngrok ERR_NGROK_3200 Ngrok टनल बंद हो गई है। npm run dev:tunnel दोबारा चलाएं और नया URL Meta/Shopify में अपडेट करें।
